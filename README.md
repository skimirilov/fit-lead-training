# Fit&Lead — локальная платформа обучения

Запуск: `python3 server.py`, затем http://127.0.0.1:8000.
Python 3.9+, внешние зависимости не нужны. Сервер слушает только этот компьютер.

## HR
http://127.0.0.1:8000/hr
При первом запуске случайный пароль создаётся в `data/hr-password.txt` (права 0600).
Можно задать переменной окружения FIT_HR_PASSWORD. Сессия HR действует 8 часов.

## Данные
SQLite: `data/training.sqlite3`. Для резервной копии остановите сервер и скопируйте папку data.
Сессия кандидата хранится в HttpOnly cookie. Код восстановления доступен после начала обучения; он секретный, как пароль. Позволяет вернуться к записи без регистрации, пока доступен тот же сервер и его база.
Дедлайн — 72 часа с нажатия «Начать обучение», рассчитывается сервером. Просрочка не блокирует прохождение. Все даты HR показаны по Москве, экспорт — UTC.

## Видео и тексты
Google Drive: три исходных MP4 встроены по их ID в web/app.js. Нужен интернет и разрешение Google Drive на просмотр видео. Автоматическое подтверждение просмотра недоступно: по согласованию с заказчиком используется явная кнопка «Я посмотрел(а) видео». Сервер проверяет последовательность, сохраняет время и не дублирует завершения.
Названия и описания блоков находятся в web/course-content.js и подготовлены по сценариям заказчика: типы блогеров, поиск, аналитика. Порядок блоков 2–3 принят по логике обучения; номер первого блока явно указан в сценарии.
Шрифт Raleway взят из переданного ZIP; лицензия в web/assets/FONT-LICENSE.txt.
Цвета из брендбука: #005856, #FDF000, #282828, #D9D9D9. Текстовая версия логотипа временная (нет отдельного векторного исходника).

## До публичного запуска
Это локальная версия, не опубликована. Нужно утвердить тексты блоков, исходник логотипа, документ и основание обработки персональных данных, сроки хранения, способ авторизации сотрудников HR и инфраструктуру размещения. Для удалённого доступа нужны HTTPS, безопасное размещение базы, Secure cookie, резервные копии и процесс выдачи HR-доступов.

## Проверка
`python3 -m unittest discover -s tests -v`
Проверяются сохранение сессии, серверная последовательность, идемпотентность, отзыв, HR-доступ, восстановление и дедлайн. Тесты используют отдельную временную базу.

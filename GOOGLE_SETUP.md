# Fit&Lead — инструкция по Google Таблице и доступам

## Что подготовлено
Интерфейс для GitHub Pages, отдельная страница HR `/hr/` и сервер Google Apps Script. Таблица создаётся в вашем Google-аккаунте при первом выполнении configure и по умолчанию остаётся закрытой. Видеоматериалы воспроизводятся из Google Drive.

## Первый запуск Google
1. Откройте проект Apps Script в обычном браузере под аккаунтом skimirilov@gmail.com. Код уже сохранён.
2. Выберите функцию configure в списке рядом с «Выполнить» и запустите её.
3. Пройдите авторизацию Google самостоятельно. Скрипту требуется право создавать и изменять Google Таблицы. Если Google показывает предупреждение о непроверенном вашем приложении, проверьте название проекта и код; этот шаг остаётся за владельцем аккаунта.
4. В журнале выполнения появится адрес созданной базы. Таблица называется «Fit&Lead — база обучения», вкладка «Кандидаты». Не включайте доступ «Все, у кого есть ссылка». Для совместной работы выдавайте доступ только нужным HR через Google-аккаунты.
5. В Apps Script нажмите «Начать развертывание» → «Новое развертывание» → тип «Веб-приложение». Выполнение — от вашего имени; доступ к API — «Все» (в том числе пользователи без Google-аккаунта). Таблица при этом не публикуется: сервер выдаёт запись кандидата только по его секретному коду, а список кандидатов — по HR-сессии.
6. Разрешение на доступ к API и права Google подтвердите как владелец. Скопируйте реальный URL веб-приложения, оканчивающийся на `/exec`.
7. В web/settings.js задайте:
   `window.FIT_SETTINGS = { backend: 'google', googleScriptUrl: '<реальный URL /exec>' };`
8. Выполните `python3 scripts/prepare_pages.py`, отправьте docs в репозиторий. В GitHub → Settings → Pages выберите Deploy from a branch, main, /docs. Публикуется только интерфейс; пароли и база в репозиторий не входят.
9. После успешной публикации откройте фактически выданный GitHub Pages адрес. HR-адрес получается добавлением `hr/` к адресу сайта. Проверьте прохождение в тестовой записи и появление результата в таблице.

## Пароли
Новый пароль HR подготовлен в локальном файле `data/Доступы.md`. Он начинает действовать в Google-версии после успешного configure. На сайт кандидатам пароль не нужен. Для Google Таблицы и редактора скрипта используется ваш существующий Google-аккаунт; отдельного Google-пароля система не создаёт.

Папка data исключена из Git. Не публикуйте файл доступов и не отправляйте кандидатам.

## Работа HR
Откройте отдельный HR-адрес и введите пароль. HR-сессия действует не более 6 часов; Google может завершить её раньше при очистке серверного кеша — просто войдите снова. Доступны список, поиск по ФИО, фильтры статуса и дат, сортировка, подробная карточка, отзывы и CSV. После работы нажмите «Выйти».

## Работа кандидата
1. Ввести ФИО, нажать «Начать обучение».
2. Прочитать предупреждение и подтвердить начало. Именно после подтверждения стартуют 72 часа.
3. По очереди посмотреть три видео и после каждого нажать «Я посмотрел(а) видео».
4. Промежуточные страницы позволяют продолжить сразу или позже. Таймер не останавливается.
5. Сохранить секретный код восстановления — он открывает свою учебную сессию на другом устройстве.
6. После третьего блока написать @daricda о завершении и при желании оставить отзыв.

## Таблица
Одна строка — один кандидат. Хранятся ФИО, даты, завершения блоков, отзыв и хеш кода восстановления. Второй столбец скрыт для удобства, а не как средство защиты: защиту обеспечивает закрытый доступ к самой таблице. Процент, статус и длительность вычисляются сервером по датам.
Не переименовывайте вкладку «Кандидаты», не переставляйте столбцы и не редактируйте служебные значения вручную: это может нарушить работу API. Для анализа создавайте отдельный лист или выгружайте CSV из HR-панели.

## Обновление и резервная копия
Тексты блоков: web/course-content.js. Видео: список ids в web/app.js.
При изменении Apps Script требуется обновить развертывание на новую версию; адрес действующего развертывания сохраните прежним. Повторный setup не очищает базу.
Для резервного копирования базы в Google Таблицах используйте «Файл» → «Создать копию», затем проверьте ограничения доступа к копии. CSV из HR-панели содержит аналитику и отзывы, но не хеши сессий и не заменяет полную копию базы.

## Ограничения и проверка
Google применяет квоты к Apps Script и Таблицам. При ошибке сохранения интерфейс не показывает успешное завершение: запрос нужно повторить. Запрос начала использует один и тот же случайный код при повторе, чтобы не создавать дубль при потере ответа. Секреты передаются в теле POST, а не в URL.
Локальные тесты Google-логики выполнены. Проверка настоящего браузерного обмена с `/exec` и публикация Pages требуют завершить авторизацию и развертывание Google. До этого публичная система не считается запущенной.

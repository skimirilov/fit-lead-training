# GitHub Pages + бесплатный сервер

Репозиторий: https://github.com/skimirilov/fit-lead-training

## Архитектура
- Статический интерфейс: GitHub Pages, папка web, включая отдельный web/hr/index.html.
- API: Render Free (без постоянного диска).
- База: PostgreSQL в Neon Free; соединение по TLS. Тариф должен оставаться Free.
- Локальная версия по-прежнему использует SQLite, если DATABASE_URL не задан.

Бесплатный Render засыпает без запросов: первый запрос после простоя может занимать около минуты. Во время ожидания нельзя повторно создавать кандидата; сессия восстанавливается по токену. Таймер рассчитывается по серверному дедлайну и не зависит от сна сервера.

## Подключение
1. Создать отдельный проект Neon на Free и получить строку соединения с sslmode=require. Не публиковать её в репозитории.
2. В подтверждённом рабочем пространстве Render создать сервис с render.yaml, план free. Задать DATABASE_URL и случайный FIT_HR_PASSWORD длиной от 16 символов в секретных переменных окружения.
3. После успешного /api/health записать реальный HTTPS-адрес API в web/settings.js: apiBase должен оканчиваться на /api/.
4. Проверить кандидатский и HR-сценарий с фронтендом на Pages. Разрешённый Origin задаётся через FIT_ALLOWED_ORIGINS, сейчас https://skimirilov.github.io.
5. В GitHub Settings → Pages включить публикацию папки /docs из main. Для подготовки docs выполнить python3 scripts/prepare_pages.py. Скрипт откажется собирать без настроенного HTTPS API, чтобы не публиковать неработающую систему.

Секреты и данные из папки data не публикуются. На разных доменах кандидатская сессия хранится в localStorage, HR-сессия — в sessionStorage и проверяется сервером. Пароль HR не передаётся в URL и не зашивается в JavaScript.

Нельзя использовать локальную SQLite на бесплатном Render: файловая система не сохраняется между перезапусками. Production-режим специально отказывается запускаться без DATABASE_URL.

## Резервные копии
Экспорт HR в CSV сохраняет аналитику и отзывы; полный дамп PostgreSQL нужно получать отдельно. CSV не заменяет резервную копию всей базы. Публичный сервис не содержит реальных кандидатских данных при первом запуске. Данные локальной SQLite автоматически не переносятся.
